⚡Grinding biomass consumes 50–65 kJ/kg — a major processing cost
🌡️Energy varies by biomass type, speed, moisture & sieve size
🔧Wrong mill parameters = wasted energy & poor particle output
🚫No real-time tool exists to predict & optimize these parameters

🎯 Objective

📊Digitize & visualize all paper experimental data interactively
🤖Train ML models for real-time energy & particle size prediction
⚡Optimize mill speed to minimize energy for any biomass type
🌐Deliver everything through a clean browser-based interface

STEP 02
🤖

Training the ML Models

We chose Polynomial Regression because the paper proves energy follows a power-type curve with R² > 0.969

Model Training (scikit-learn)
from sklearn.preprocessing import (
  PolynomialFeatures )
from sklearn.linear_model import Ridge
from sklearn.pipeline import Pipeline

def build_model(degree=2, alpha=0.01):
  return Pipeline([
    ("poly", PolynomialFeatures(
               degree=degree)),
    ("reg",  Ridge(alpha=alpha)),
  ])

# Train per biomass type
for biomass in biomass_types:
  X = speeds.reshape(-1, 1)
  y = energy_values[biomass]
  model = build_model().fit(X, y)
Why Per-Biomass Models?
❌ Single model (all biomass)
R² ≈ 0.64
Integer encoding biomass type creates meaningless polynomial cross-terms
✅ One model per biomass
R² ≈ 0.99
Each biomass has its own physical grinding behavior — separate models fit perfectly
📐 Input: [speed] → PolynomialFeatures → [1, speed, speed²] → Ridge → prediction

Building the FastAPI Backend

FastAPI automatically generates a REST API — models load once at startup, predictions are served in milliseconds

API Endpoint (app.py)
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class KnifeRequest(BaseModel):
  biomass_type: str
  speed: float

@app.post("/api/predict/knife-mill")
async def predict(req: KnifeRequest):
  energy, power, particle = \
    predict_knife(req.biomass_type,
                  req.speed)
  return {
    "predictions": {
      "specific_energy_mj_per_kg":
         round(energy, 4),
      "mean_power_watts":
         round(power, 1),
    }
  }

How the Optimization Engine Works

We sweep every possible RPM value, score each one, and return the minimum — no fancy solver needed

Optimization Algorithm (app.py)
# Sweep 60 speed values from
# 3000 to 9000 rpm
for speed in range(3000,9001,100):
  energy, power, particle = \
    predict_knife(biomass, speed)

  # Score = energy + particle
  # penalty if target given
  score = energy
  if target_particle_size:
    score += abs(particle
      - target_particle_size) * 0.5

  results.append({
    "speed": speed,
    "energy": energy,
    "score": score
  })

# Return lowest scoring point
optimal = min(results,
  key=lambda r: r["score"])
1User picks biomass + optional target particle size
↓
2Backend sweeps 60 speed values (3000 → 9000 rpm)
↓
3ML model predicts energy + particle size at each speed
↓
4Score = energy + penalty if particle size deviates from target
↓
5Return speed with lowest score → shown with full sweep chart
